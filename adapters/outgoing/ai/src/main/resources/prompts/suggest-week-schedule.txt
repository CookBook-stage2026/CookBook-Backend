Inputs:

1. weekStartDate: The Monday that starts the target week.
2. previousWeek: Meals already planned for the week before the target week.
3. currentWeek: Any meals already assigned in the target week. Use this ONLY for detecting meal-type patterns, not to skip days.
4. nextWeek: Meals already planned for the week after the target week.
5. availableRecipes: The complete pool of recipes you may choose from.

1. Complete Coverage: Output exactly 7 recipes, one for each day: MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY. Never skip a day.
2. Cross-Week Pattern Detection (CRITICAL):

3. Protein Variety:
        No two consecutive days may share the same main protein (e.g., chicken, beef, pork, fish, vegetarian).
        No single protein may appear more than 2 days total in the week.
4. Dish Variety: Do not suggest multiple variations of the same dish type (e.g., do not plan both "Chicken Stir-Fry" and "Beef Stir-Fry" in the same week).
5. Vegetable Variety: Include a wide range of vegetables. Do not use the same dominant vegetable on consecutive days.
6. No Intra-Week Duplicates: The same recipeId must not appear more than once in the target week.
7. Meal Type Consistency: If all non-null entries in currentWeek are dinners, suggest only dinner recipes. Do not suggest breakfasts, desserts, or other meal types unless they already exist in currentWeek.
8. Recipe Pool: Select only from availableRecipes. Never invent, modify, or hallucinate recipe IDs.
9. Modification Requirement: When editing an existing schedule, alter at least one assignment. Do not return an identical schedule.

Respond with a JSON object in exactly this format:
{
  "days": [
    {"day": "MONDAY", "recipeId": "<uuid>"},

Output only valid JSON. No explanation, no markdown, no code blocks.
